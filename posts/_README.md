# 文章目录

这个目录里的每个 `.md` 文件就是一篇博客文章。文件名（去掉 `.md`）会出现在网址里，建议用 `YYYY-MM-DD-短标题.md`，只用英文和连字符。

## 写一篇新文章

1. 复制 `_template.md`，改成上面的命名格式；
2. 填好开头 `---` 之间的元数据；
3. 正文用 Markdown 写；
4. 提交并推送到 `main`。

推送后 GitHub Action 会自动重新生成 `posts/index.json`，博客列表随即更新——不需要手动改任何列表文件。

## 元数据

```yaml
---
title: 文章标题
date: 2026-10-17
updated: 2026-10-17
summary: 列表页显示的一句话摘要。
tags: 标签一, 标签二
---
```

| 字段 | 必填 | 说明 |
|------|------|------|
| `title` | 是 | 文章标题 |
| `date` | 是 | 发布日期，`YYYY-MM-DD` |
| `updated` | 否 | 最后修改日期；不写则由构建脚本取该文件最后一次 git 提交的时间 |
| `summary` | 否 | 列表页摘要；不写则取正文第一段 |
| `tags` | 否 | 逗号分隔，中文逗号也可以 |

## 图片

图片放在这个目录下，正文里用 `![说明](文件名.png)` 引用即可。文件名同样建议用英文。

## 本地预览

改完文章后，在仓库根目录运行：

```bash
node scripts/build-posts.mjs
```

然后起一个静态服务器（比如 `python -m http.server`）打开 `/blog/` 查看。不跑这一步也行，下次推送时 Action 会补上。

以下划线开头的文件（如 `_template.md`、`_README.md`）不会被当成文章。
